# ADR 0005 · Catalog imports, quality checks and alerts

## Context

Warehouse staff need repeatable opening balances and alerts before the procurement and notification delivery phases exist. Mobile browsers differ in camera barcode support.

## Decision

CSV files use UTF-8. Excel files use a single XLSX sheet with plain values. A file is limited to 2 MiB and 500 data rows. The dry run parses and validates without writes. The commit revalidates and posts the whole file in one database transaction. Item and supplier rows replace the supplied catalog record by code, including its optional fields. Opening rows go through the receipt service. Their UUIDs derive from the import UUID and row number, so an HTTP retry does not add stock again.

New lots start in quarantine. An existing quarantined lot accepts additional stock only when supplier, expiry and receipt reference match. An inspected lot cannot receive additional quantity under the same lot identity. Items, locations and warehouses with positive stock cannot be archived. An item's base unit and storage condition, and a location's warehouse and storage condition, become fixed at the first posting.

Minimum and maximum thresholds use total physical stock across warehouses. Expiry alerts cover every on-hand dated lot. Celery beat refreshes conditions every five minutes. When a condition clears, its notification receives a resolution timestamp. A recurrence creates a new notification.

Use native browser barcode detection as a progressive enhancement. Item labels may encode an item code or a registered barcode. Stocktake labels may encode an unambiguous lot number or `ITEM:LOT`. All flows accept manual entry.

## Consequences

Dry-run results are advisory until the commit obtains locks. Currency remains UZS in Phase 1. Supplier tax IDs are omitted from audit snapshots and access to them is recorded. Redis and PostgreSQL must both be available for background refresh. Phone cameras require a secure browser context and a browser that exposes barcode detection.
