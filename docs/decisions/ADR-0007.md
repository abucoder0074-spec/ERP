# ADR 0007 · Receipts, invoice matching and private attachments

## Context

Receiving must use the Phase 1 ledger. Supplier evidence can include private business information. Partial delivery and defective stock must not permit duplicate billing.

## Decision

Post each receipt line through the inventory receipt service. Apply the configured over-delivery limit to cumulative net receipts across order versions. Unplanned items need an explicit permission and reason. Return defective goods through the inventory return service with a reason and photo. Measure deliveries against the promised date on the version received, and count defective receipt lines by supplier.

Match each invoice line to a specific receipt line and the order version it references. Compare net quantity and document-currency unit price using configurable percentages. An invoice reserves its receipt lines until cancelled. Mismatches retain reason codes and block readiness until a permitted user records an override reason. Supplier and invoice number are unique across all states.

Keep attachments in PostgreSQL with random UUID storage names, so upload metadata and bytes commit together outside the web root. Stream only through an authenticated document-permission check. Validate bounded JPEG, PNG and PDF content. Invoke a configured scan hook before persistence. The default hook is a no-op.

## Consequences

Returns and amendments revalidate affected commercial invariants under the order lock. A database backup includes attachments. Configure a real scanner before accepting untrusted production files. Automatic delivery of RFQs, payments and supplier ledger entries are later scope.
